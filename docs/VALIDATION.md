# 平台验收与有限结论

这里记录的是有限样本证据，不是全部版本、全部历史或未来应用的兼容保证。真实材料、截图、数据库和备份不随发布物提供。历史实机回执不是对当前版本每次改动的重新认证。

## 近期样本与当前结论

四端独立实验已运行，覆盖以下有限样本。大部分真实应用证据来自 0.4.0 的早期预览版。后续小版本主要有自动回归和工具包自测，另有 preview.7 的 Windows Codex → Claude 真实样本，以及 preview.8 的 Windows、macOS Claude 新副本冒烟（恢复、桌面打开、续聊、看图）。preview.8 没有单独冒烟 Codex 原生恢复，其路径在 preview.6 到 preview.8 没有改动。preview.9 只改文档。0.4.0 在此基础上只改了打包后的提示输出、图片损失标签和文档，并在 Windows 上跑过一次隔离的打包和恢复；Mac 没有因此重测。以下结果取代历史记录中“尚未执行四端实验”“macOS 原生 Codex 加载未验收”等全局待测判断。早期记录中的待测项仍描述各自样本。

0.5.0 新增批量搬家和全局规则：Windows 桌面版上 Codex → Claude、Claude → Codex 各 3 个合成项目批量恢复、历史和续聊通过；Claude 信任根目录一次即覆盖子项目；Codex 每个项目仍需各自确认信任；全局规则在两端的新会话中都被加载（项目级同路径测试）。Mac 未在 0.5.0 上重测。

### 真实长项目转换

一个真实 Codex 项目在 Windows 上转到 Claude：9 条会话，最长 106 轮，项目文件约 5.7 GB，来源含多次原生压缩。写入和登记都完成，桌面可以打开。超过默认预算的长会话，模型上下文只有陈述式提要和最近 0 到 4 轮原文。

抽查 3 条会话的续聊：模型能说清整体内容和结尾；提要没有的早期细节，模型回答不确定，没有编造；允许查阅项目内归档后，抽查的 2 条都找回了早期细节。其余 6 条只核对了写入。来源临时目录里已被删除的 2 张图片无法打包，并列入跳过清单。保留下来的历史图片都在压缩点之前，模型默认看不到，要查阅归档或历史。

### 已知限制

1. 跨 Agent 转换保留可见历史，跳过来源压缩摘要和加密项，并列出损失。模型上下文可能与来源不同。
2. 压缩由用户在应用中手动触发。本工具不会执行压缩。
3. Codex 同类样本可带着原生压缩记录续聊。答案也可能来自保留的明文，尚未证明加密项被解开。
4. 跨账号没有验证。跨机回执没有确认账号是否相同。
5. 已测的 Codex 会话在后续轮次没有重新记录 Skill 目录，跨机后历史中的目录仍指向来源机。读取目标 Skill 文件的成功样本未证明原生发现。
6. Claude 快进检测依据命令行和会话进程记录，可能误拦，也可能漏检：没有发现不等于绝对没有运行中的进程。会话若还在别处打开，需先关闭再预演。
7. Claude 桌面版需重启以加载新登记，目录信任由用户处理。Codex 在部分样本中未提示信任。
8. 压缩后实际上下文不一定明显变小。Claude 有一组样本的实际用量约从 78,259 变为 77,251 token。
9. 图片缩略图、点击和项目归组的桌面视觉覆盖有限。原生接口及记录可核对数据和绑定，实际显示另行验证。

未覆盖的实机路线包括 macOS 来源的压缩与附图跨机恢复、macOS 上含压缩来源的跨 Agent 转换和 Mac Codex 接收这类转换包。Claude 新副本追加的标题记录在两平台的真实桌面不影响加载和续聊；终端 `--resume` 列表的显示待验收。Linux 和其他 Agent 未覆盖。

## 其他兼容性及历史诊断

- Python 3.11加临时zstandard 0.25.0实际解压合成与本机压缩来源通过；compression.zstd和系统zstd分支有模拟测试，未在实际Python 3.14或系统zstd命令上完成同等实测。未压缩来源不需要可选依赖。
- Windows合成回归覆盖旧Codex事件、压缩路径、归档、根别名、子目录cwd、二进制旁车、重复目标、原生文件头和损失分类；当前21组测试不是21种平台的验收。
- 早期 macOS 绑定修正样本是在先前修正后的同一Codex会话上一次续聊保持绑定，实际resume/turn-start参数未取得。后续的 macOS Claude → Codex 样本也不能证明cwd漂移根因已修复或所有新导入都会稳定。始终执行[绑定前后独立核对](CODEX_PROJECT_BINDING.md)。

## preview.2 追加验收

- 早期 macOS 往返样本的真实双会话项目完成 Windows → Mac → Windows 原生迁移。Mac 续聊新增的完成轮次在 Windows 原生接口可读，原有会话和历史前缀保留。另有一个 Mac 原生 Codex 会话在 Windows 加载了 8 轮历史。
- Claude 往返回包通过严格前缀比较，Windows 只追加了 19 行。该证据覆盖文件写回，桌面界面验证另行记录。Mac Claude 的项目配置观察促成了 MCP 文件隔离。
- Windows 合成项目实际打包并恢复了 4 GiB + 1 MiB 的单文件，以及总计 2 GiB + 2 MiB 的两文件项目。三个独立进程的峰值工作集约 25 MB，包括 8 MiB 对照。此测量针对项目文件复制，不代表任意大小的会话历史占用固定内存。
- Mac Codex 自动登记项目仍需原生 App 处理。界面与外部附件覆盖有限，应用加载后的权限遵循目标 App。四端独立测试环境的验收尚待执行。
