# 迁移故障恢复

迁移或验收遇到故障时，从当前回执、命令实际报错、目标应用的原生状态取证。记录来源和目标应用、系统与版本、本次导入 ID、预期项目路径以及已完成的阶段。先核对回执里的 ID 和路径，尤其是目标目录重名、同一会话已有多个副本或任务状态显示等待时。

证据符合下列条件且所需操作已经授权时，Agent 直接修复，无需重复征求同一项授权。从原回执继续，只执行缺失或失败的步骤。复查后仍有同一问题时，只有发现并解决了新的具体原因才再尝试。记录修复前后状态、命令结果及备份位置。按文件、历史、登记、左栏、附件和续聊分别更新验收状态。

## 文件和历史已恢复，左栏或归组缺失

- **Codex。** 从回执读取本批会话 ID 和目标根路径。登记回执为 pending 或超时时，先用原生列表核对已有项目。项目已存在时直接绑定缺失的会话。绑定提示会话尚未进入侧栏时，按 ID 原生打开一次，再重试一次绑定。按项目 ID 和完整 cwd 复查每条会话。看到真实信任提示时，停在该项目等用户亲手确认，随后从原回执继续。具体调用顺序见 [Codex 项目绑定](CODEX_PROJECT_BINDING.md)。
- **DSH。** 已有本次恢复回执 `.rehome/restore-dsh.json`，日志 ID、cwd 和 V4 文件都匹配，但注册表尚无对应归属时，先用 `dsh_native.py --probe --dsh-home <目标数据根>` 核对初始化的 workspace v2。确认宿主已停止后，按 Skill 中的 `--register-offline` 命令为这批记录补登记，传入新的备份文件。宿主重开后打开原会话，复查左栏、标题和 cwd。
- **Claude。** 仅在便携单会话导入回执存在、目标历史未续聊或改动、原包和目标路径均一致、且本轮对应桌面登记缺失时，先对原导入命令运行 `--dry-run`。预演返回 `already-imported` 并给出预期登记路径时，以同一组导入参数去掉 `--dry-run`，由导入器备份并补登记。原样平移、整项目恢复或既有登记冲突时，按对应原生流程核实加载状态。桌面需重开时由用户操作，重开后按原 ID 核对。
- **WorkBuddy。** `.rehome/restore-workbuddy.json` 显示 `workspace-ready` 时，核实本批会话尚未原生登记、目标历史目录尚未写入，再按 Skill 所列的模板空间和平台条件执行 `workbuddy_native.py`。已有成功登记时，从原回执开项目和会话验收。若历史目录、索引和回执不一致，保留原项目和备份，先在隔离目录复现。

## 左栏正确，工作目录不对

分别核对归属、当前 cwd 和最近的历史上下文。Codex 使用原生列表和 `read_thread`，再用 `check_codex_binding.py` 检查当前数据库与会话头。已证实归组本身错误时，先按精确项目路径修正归组，再读取 cwd。归组已正确而 cwd 仍错误时，只有当前原生接口明确提供 cwd 参数，并已有本次测试续聊授权，才显式传入核实过的工作目录做一次复验。确认当轮 cwd 和续聊后的状态。发现续聊后仍漂移时，暂停该会话的项目操作，保留前后结果。旧历史里的路径属于历史证据。

## 历史附件打不开或挂错轮次

从原消息、包内清单和目标文件分别核对附件引用、实际位置与哈希。包里字节完整时，用当前对应的目标写入器在隔离副本重现。Claude 已恢复 TXT 再次导出或同时间戳的轮次关联异常时，用当前 `project_rehome.py pack --from claude` 从原工作区重打一个新包，核对每个附件仍绑定到原用户消息。DSH 导出到 WorkBuddy 时，用当前 DSH 导出器重新打包，以附件元数据携带已核对的文件。两个方向都应在隔离副本先验哈希和原消息位置，再按授权范围用目标界面打开附件。只有来源能找回所需字节时，才继续恢复缺失或损坏的附件。保留已经续聊的目标会话。

## 无法启动、登录或缺少解压依赖

来源应用无法启动或登录时，读其受支持的本地历史直接导出。目标运行不了时，先交付能够核对的项目文件、历史和附件，原生验收保持待验。DSH 先执行只读预检，核对架构、Python 和已有 Zstandard 后端。在已安装且兼容的解释器之间可直接切换，按用户授权决定是否准备依赖。需要更换 DSH 运行方式时按 [运行环境判断](DSH_RUNTIME.md) 核实目标宿主及数据格式。现有环境无法解析压缩历史时，继续包和普通项目文件检查，明确哪部分写入或原生测试仍受阻。

未知格式、校验失败、身份或路径冲突、正在写入的数据，以及权限或信任拒绝，都需要先解决对应原因。保留原件、备份和能复核的前后证据。按 Skill 的既有操作权限继续其他独立步骤。
